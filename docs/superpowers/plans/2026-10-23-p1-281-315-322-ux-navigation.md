# Group 1 UX/Navigation Batch (#281, #315, #322) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship three independent P1/P3 UX issues as one batch branch off latest `main`: per-card credit utilization breakdown on Health (#281), a real category filter on Ledger plus Spending→Ledger cross-navigation (#315), and a tabbed Settings modal (#322).

**Architecture:** Each issue is additive to an existing render function and does not change any data model. #281 adds a collapsible per-card list to the existing Credit Utilization health card, reusing `creditUtilizationStatus`/`statusFillCls`. #315 adds a first-class `app._ledgerCategoryFilter` alongside the existing account/date/cleared filters in `getFilteredSortedLedgerTransactions`, and adds a "View in Ledger →" link to the *existing* Spending category drill-down modal (not a change to what clicking a category row does, which already opens that modal) that sets the filter and navigates. #322 wraps the existing `#settingsModal` form-groups into four `role="tablist"` panels using the exact CSS/JS pattern already shipped for the Data Transfer modal's Export/Import tabs (`.dt-tab-btn`/`.dt-tab-panel`), with its own `.settings-tab-*` classes.

**Tech Stack:** Vanilla ES6 modules, no build step, Chart.js (no chart work here), Playwright/pytest for tests.

**Spec:** GitHub issues [#281](https://github.com/jasonkryst/MyFinances/issues/281), [#315](https://github.com/jasonkryst/MyFinances/issues/315), [#322](https://github.com/jasonkryst/MyFinances/issues/322) — acceptance criteria quoted inline per task below, with corrections where an issue's "Notes" section described code that doesn't actually exist (see Task 2).

## Global Constraints

- No build step — `index.html` script order is load-bearing; don't add new `<script>` tags.
- Strict CSP: no inline `<style>`/`<script>`, no `eval`. All visibility toggles via `classList`/`hidden`, matching the existing `.dt-tab-btn`/`.dt-tab-panel` and `healthSurplusTxToggle` patterns.
- All user-rendered strings via `innerHTML` must go through `escapeHtml()` (from `utils.js`); prefer `textContent`.
- Every feature-module function takes `app` as its first argument; add a one-line delegating method on `DebtTrackerApp` in `src/app.js` for any new function other code needs to call from outside its own module.
- `APP_VERSION` (`src/utils.js`) and `sw.js`'s `CACHE_NAME` must be bumped together; every bump needs a matching `CHANGELOG.md` entry (`tests/features/test_versioning.py` enforces this) and a `WHATS_NEW_ENTRIES` entry in `src/ui.js` within 3 minor versions of the running version (`tests/features/test_whats_new.py`).
- Chart accessibility (`renderChartDataTable`) is N/A — none of these three issues touch a chart.

## Review Focus

- **#281:** A user with credit-card debts but *none* carrying a credit limit currently sees only the card's generic empty state — the per-card list must still surface those cards (labeled "No limit set") rather than silently vanishing along with the aggregate figure.
- **#281:** A debt record with `debtType: 'creditCard'` but `creditLimit: 0` (not `null`) must be treated as "no limit set", not divide-by-zero into a bogus 0%/Infinity utilization.
- **#315:** Categories on the Ledger's new filter dropdown must come from the full unfiltered transaction set (like the existing Account dropdown), not from whatever the *other* active filters currently show — otherwise picking an account filter first could make a category silently disappear from its own dropdown.
- **#315:** The "View in Ledger →" cross-nav must not corrupt the Ledger's *persisted* filter state for a user's next unrelated visit — the account/date-range reset it performs on cross-nav should not be written to `debtTrackerLedgerFilters` in a way that silently overrides a filter the user had deliberately set and saved before.
- **#322:** Moving existing settings controls into tab panels changes which ones are reachable/focusable without an extra click — any Playwright test that drives those controls directly (several do, across `test_setup_wizard.py`, `test_postgres_*.py`, `test_debts.py`, `test_reports.py`, `test_i18n.py`, `test_accessibility.py`) must be updated to click the right tab first, or it will start failing on an invisible/unfocusable element.

const tabBtns = modal.querySelectorAll('.settings-tab-btn');

function showSettingsTab(tab) {
