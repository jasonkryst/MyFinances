# MyFinances i18n Audit — 2026-11-04

**App version audited:** 7.0.0 (`main` at `3d156a1`, PR #458 merged; audited from branch `docs/v7-security-audit`)
**Scope:** Locale-file parity and coverage; the v7 surfaces added in PR #458 (`serverGate.*`, `sync.*`, `pgMigration.*`, Settings storage info, What's New); hardcoded user-visible English across `src/` and `index.html`; translation quality of the v7 strings in `es`/`pl`; plurals; date/number/currency formatting; live locale switching; server-side user-facing text; gaps in the automated guard.
**Prior audit:** `i18n/I18N_AUDIT_2026-10-06.md` (app v6.10.7)

**Method (what actually ran):**

| Tool | What it did |
|---|---|
| `pytest tests/features/test_i18n_coverage.py` (full, against the local Postgres stack at `http://localhost:32901/`) | Key parity, orphan keys, placeholder parity, English-stub check, `SAME_AS_ENGLISH` staleness, and the pseudo-locale render guard over every `TRANSLATED_PAGES` entry (seeded and empty data). **175 passed in 564 s.** |
| Node (`import()` of `src/locales/*.js`) | Key counts per locale; classification of every `.one`/`.other` plural base in `pl.js`; `Intl.PluralRules` category check for `pl-PL`/`es-ES`. |
| Python `html.parser` scan of `index.html` (scratch script) | Every text node / `aria-label` / `title` / `placeholder` / `alt` with letters and no `data-i18n` / `data-i18n-attr`, grouped by enclosing section or modal. 66 hits. |
| `grep` / ripgrep over `src/`, `server/src/` | Literals assigned to `textContent`/`innerHTML`/attributes, `showAlertModal`/toast text, Chart.js labels and tick callbacks, `toLocaleDateString`, `toFixed`, hardcoded `$`, files with no `t()` import. |
| Playwright (Chromium) live check against the local stack, seeded with the coverage test's `SEEDED_STATE` | `setLocale()` to `es` then `pl`; read the `<html lang>` attribute, Health page text, account menu, command palette, What's New, Keyboard Shortcuts, Settings storage info, sync banner, server-unreachable gate, legacy-data modal, `plural()` output, setup wizard and account-replacement modal markup, `document.title`. |
| `git diff 13c72cd..3d156a1` | Every string added or changed by v7. |

No app code or tests were changed. Findings marked *(inferred)* were not reproduced at runtime.

## Summary

| Severity | Count |
|---|---|
| High | 2 |
| Medium | 6 |
| Low | 8 |

The v7 strings themselves are in good shape: every new key exists in all three locales, placeholders match, the render guard covers all four new surfaces, and the es/pl copy matches the English meaning. The problems are outside v7. The **Health page**, which is the default landing page, still has large English-only sections, and the guard never scans it. The **global chrome** (account menu, command palette, Keyboard Shortcuts, What's New) is English in every locale. The new findings come from areas the render guard doesn't reach, not from regressions in guarded pages.
